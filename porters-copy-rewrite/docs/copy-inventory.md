## 1. EDIT ARCHITECTURE

### 1.1 The headline finding: this site has a live CMS that overrides the source

`docs/CMS.md` and `src/components/cms/CmsRuntime.astro` document a Supabase-backed visual CMS.
Every public route is wired to it. The behaviour is:

```
1. Astro renders the hardcoded French text from source  → SEO-safe fallback, in the HTML
2. After paint, CmsRuntime fetches published overrides from Supabase for the current route
3. If a published row exists for a key, it REPLACES the rendered text in the DOM
```

**Consequence for this rewrite:** editing a source file changes the fallback, not necessarily what
a visitor sees. If an administrator has ever published that block through `/admin/editor`, the
Supabase row wins and the source edit is invisible on the live site.

The registry states the current rollout scope: **all 54 public routes, 2 250 keys, including 74
shared header/footer keys** (`docs/CMS.md`, "Current rollout scope").

> 🔴 **Question for the client, before Phase 1 commits:**
> Has anything been published through the CMS editor on production? If yes, every rewritten block
> also needs its Supabase row updated or reset, or the rewrite will not appear. This is a delivery
> question, not a copy question, but it decides whether Phase 1 is visible at all.
> → recorded as **N7** in §8.3.

### 1.2 Four copy layers, in order of how much text they hold

| Layer | Path | What lives there | Editable in this pass |
|---|---|---|---|
| **A · Explicit CMS registry** | `src/cms/content-registry.json` | 96 human-named keys. **All homepage copy**, hero included. | ✅ Yes — this is the homepage edit surface |
| **B · Data / content modules** | `src/data/*.ts`, `src/content/pages/*.ts` | FAQ, expertises, agencies, benefits, about, consultants, entreprises | ✅ Yes |
| **C · Hardcoded in `.astro`** | `src/pages/**`, `src/components/**` | Every other page's headings, leads, CTAs, card copy | ✅ Yes |
| **D · Generated / derived** | `src/cms/auto-content-registry.json`, `src/cms/editable-pages.json`, `supabase/migrations/*_seed_all_routes_cms.sql` | 2 517 auto-discovered fallbacks, regenerated by `npm run cms:discover` | ⚠️ Never hand-edit — regenerate |

**There is no i18n setup and no Astro content collection.** `src/content/` is a plain TS module
directory, not `astro:content`. French is the only locale; no locale files exist.

### 1.3 Layer D — the synchronisation trap

`npm run cms:discover` rebuilds the site and regenerates the auto registry, the editable-page list,
and an idempotent seed migration. After any copy commit, layer D is **stale**: it still holds the
old French sentence as the CMS fallback.

Per `docs/CMS.md` the documented procedure is: change the text → run `npm run cms:discover` →
commit the regenerated registry + migration → apply the migration.

> ⚠️ **Scope conflict to resolve before Phase 1.** `copy-plan.md` §10.1 forbids touching config and
> build artefacts. Layer D is neither exactly — it is generated content that mirrors the copy. Two
> defensible readings:
>
> - **(a)** Copy commits stay text-only; a single regeneration commit runs at the end of the whole rewrite.
> - **(b)** Each copy commit carries its own regenerated layer D, keeping registry and source in step.
>
> **Recommendation: (a).** It keeps the one-page-per-commit reviews readable — regenerating layer D
> produces a ~500 KB diff that would bury the actual copy change — and the fallback staleness has
> no user-visible effect while the source render is what ships. But it is the client's call, and it
> must be decided before the first commit, not after. → **N8** in §8.3.

### 2.1 Structural divergence from `nav-plan.md` §4

The plan proposes **four expertise anchors on one page** (`/expertises#cyber` etc.). The repo has
**five separate expertise pages** already built, indexed, and carrying `Service` JSON-LD.

Converting five pages into four anchors is a **T3 change** — deleting four routes. `nav-plan.md`
§6 forbids it in this pass, and §7 would require a redirect protocol. Phase 4 must therefore rewrite
the five existing pages in place. The anchors idea is a separate, budgeted phase.

`/expertises/product-project-management` exists but appears nowhere in `copy-plan.md` or
`nav-plan.md`. Someone has to decide whether it is a fifth hub or a page to fold into another. → **N9**.
